## 1. Purpose & Architecture

The **RESQ-AI Grounded Emergency Action Plan Engine** transforms deterministic, verified outputs from the Risk Engine, Emergency Priority Engine, Route Risk Engine, and dataset feature stores into concise, explainable, human-readable operational action plans.

```
Structured RESQ-AI Evidence (Risk / Priority / Route Engines)
                         ↓
              Grounded Context Builder (grounded_context.py)
                         ↓
            Strict Prompt Builder (prompt_builder.py)
                         ↓
       LLM Client / Fallback Pipeline (llm_client.py)
                         ↓
          Output Validator & Guardrails (validation.py)
                         ↓
           Validated Emergency Action Plan
```

> [!IMPORTANT]
> **Source of Truth & Operational Disclaimers**:
> - *"The LLM does not generate the underlying risk, priority, or routing intelligence."*
> - *"RESQ-AI action plans are decision-support outputs and should be reviewed by authorized emergency personnel."*
> - *"LLM integration interface validated; deterministic fallback used because no LLM credentials were configured."*

## 2. LLM Grounding & Zero-Hallucination Guardrails

The LLM serves strictly as an operational summarization assistant and **never** as a source of numerical truth. All numerical scores (`risk_score`, `priority_score`, `route_risk_score`), risk levels, priority levels, and physical features are copied from verified engine data rather than regenerated by the LLM.

### Strict Prompt Rules (`action_plan/prompt_builder.py`)
1. Use ONLY the supplied RESQ-AI context provided in the prompt.
2. Do NOT invent facts or extrapolate unverified information.
3. Do NOT estimate missing population numbers or demographics.
4. Do NOT estimate casualties, fatalities, or injury counts.
5. Do NOT invent infrastructure damage (bridges, buildings, hospitals, schools).
6. Do NOT invent active road closures, traffic congestion, or debris.
7. Do NOT invent flood water depths or river inundation levels.
8. Do NOT invent specific evacuation times or troop dispatch counts.
9. Do NOT convert risk scores into calibrated probabilities or percentages.
10. Do NOT claim guaranteed safety, total immunity, or guaranteed evacuation success.

---

## 3. Deterministic Fallback Engine

If no LLM API key (e.g. `OPENAI_API_KEY`) is configured in the environment, or if the LLM API query times out or fails schema validation, the engine seamlessly invokes a zero-dependency **Deterministic Fallback Engine** (`generate_deterministic_fallback_plan`). 

This engine generates evidence-based operational recommendations directly from priority levels (`P1`–`P4`), vulnerability flags (`HIGH_FLOOD_SUSCEPTIBILITY`, `HIGH_HISTORICAL_FLOOD_RECURRENCE`), and evaluated route corridors without breaking execution.

---

## 4. Output Validation & Guardrails (`action_plan/validation.py`)

Every generated action plan payload undergoes strict deterministic validation before returning:
- **Schema Validation**: Checks JSON structure, required fields, and score bounds $[0, 100]$.
- **Numerical Grounding Check**: Verifies that generated risk and priority scores match the grounded context values exactly.
- **Unsupported Claim Guardrail**: Scans all generated text fields for forbidden absolute claim keywords (`"guaranteed"`, `"definitely"`, `"will flood"`, `"will be safe"`, `"road is blocked"`, `"bridge is damaged"`, casualty/fatality claims). Any match triggers immediate rejection and fallback.
